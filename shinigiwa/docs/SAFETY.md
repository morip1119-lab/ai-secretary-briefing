# 安全・法務メモ

法律の専門家による助言ではない。判断に迷う題材は、投稿しないのが最も安い。

---

## 1. 死者を扱うときの名誉毀損

日本の刑法230条2項は、死者に対する名誉毀損を **「虚偽の事実を摘示した場合」** に限って処罰する。
つまり **事実であれば原則として問題にならない** が、裏を返せば **間違えた瞬間に成立しうる**。

さらに、故人の記述が **遺族本人の社会的評価** を下げる場合は、遺族に対する名誉毀損や不法行為として
民事の対象になりうる。「もう亡くなっているから何を書いてもいい」は成り立たない。

### この システムでの扱い

- `sources` を必須にして、確認していない事実を書けないようにしている
- `causeConfirmed: false` の題材は「〜とされる」等のヘッジ表現が無いと弾く
- 「殺された」「犯人は」「隠蔽した」などの断定語を警告に出す
- **存命の関係者**（遺族・元パートナー・関係企業）を犯人扱いする記述は書かない

## 2. 没後年数

**現在の設定では、没後年数によるブロックをかけていない**（`safety.minYearsSinceDeath: 0`）。
記憶が新しい題材ほど反応が大きいため、`scorer` はむしろ没後20年以内に加点している。

これは意図的に取ったリスクなので、代わりに何が起きるかを把握しておくこと。

- 遺族・関係者が能動的に SNS を見ている
- 死因が確定していない、裁判が継続中であることが多い
- 「まだ生々しい」という理由だけで炎上しうる

没後7年以内の題材には guard が警告を出す（`safety.recentDeathWarnYears`）。
この警告が出た原稿は、**必ず出典に当たって数字を確認してから出す**。自動承認も既定で止まる。

**係争中の事案は年数に関係なく扱わない。** ここだけは緩めないこと。

きつくしたくなったら 1 行戻すだけでいい。

```jsonc
"safety": { "minYearsSinceDeath": 3 }
```

## 3. 自殺の扱い

WHO の「自殺報道ガイドライン」に沿った運用にしている。伸びる題材ではあるが、扱いを間違えると
人を実際に傷つけるうえ、X のポリシー違反にもなりうる。

### いま有効になっている制約

- **手段・場所を具体的に書かない**（`safety.methodDetailPatterns` で機械的に弾く）
- 自殺を美化・英雄視するニュアンスの語を検出したら警告する
- センセーショナルな見出しにしない

### 相談窓口の併記

**現在の設定では自動付与していない**（`safety.suicideFooter` が空）。
WHO のガイドラインは併記を推奨しているので、これは推奨から外れた運用になっている。

付ける設定に戻す場合は、文字列を入れるだけで必須化される。

```jsonc
"safety": {
  "suicideFooter": "※ こころの相談は「いのちの電話」0570-783-556 / #いのちSOS 0120-061-338"
}
```

自殺の題材そのものを扱いたくない場合は次の1行。

```jsonc
"safety": { "suicidePolicy": "block" }
```

## 4. 著作権・肖像権

### 画像

**報道写真・スチール写真・SNS からの転載は使わない。** 例外なく権利者がいる。

このシステムが既定で生成するのは文字だけのオリジナルカードで、権利の問題が発生しない。
これは安全対策であると同時に、収益化の「オリジナルコンテンツ」評価にも効く。

どうしても人物写真を使いたい場合は、
- パブリックドメイン（著作権保護期間満了）
- Wikimedia Commons の CC ライセンス（**表示義務あり**。ライセンス名と作者名を画像内に焼き込む）

のいずれかに限る。「ネットで拾った」は論外。

### 文章

Wikipedia の本文は **CC BY-SA** であり、丸写しには帰属表示と同一ライセンスでの公開が要る。
**事実だけを取り出して、自分の言葉で書き直す。** 事実そのものに著作権はない。

他アカウントの投稿の言い回しをなぞるのも避ける。X の収益化ポリシーは複製コンテンツを明確に排除している。

---

## 5. X のルール

- 自動投稿そのものは禁止されていないが、**スパム的な大量投稿・重複投稿は禁止**
- 同じ内容の再投稿は避ける（`minGapDaysSameSubject` で180日空けている）
- センシティブメディアの規定に触れる画像は載せない（遺体・事故現場など。そもそも文字カードしか作らない）
- 複数アカウントで同じ内容を投げる運用はしない

---

## 6. 投稿前チェックリスト

`guard` が機械的に見られるのは形式だけ。以下は人間が見る。

- [ ] 年号・年齢・金額を出典と突き合わせたか
- [ ] 「〜とされる」で書くべき箇所を断定していないか
- [ ] 存命の人物を悪者として描いていないか
- [ ] 事実の順序だけで語れているか（形容詞で煽っていないか）
- [ ] 遺族がこの投稿を読んだとして、事実誤認で怒られる箇所はないか
- [ ] 独自の視点セクションが、他人の意見の受け売りになっていないか

最後の項目は品質の話に見えて、収益化の審査に直結する。

---

## 7. 間違えたときの対応

事実誤認が判明したら、**言い訳をせずに即削除して、訂正を単独ポストで出す**。

引用リポストで指摘が伸びている状態を放置するのが一番損害が大きい。
削除したら `data/posts/<id>.json` の `status` を `rejected` に戻し、`data/subjects.json` の
該当データを修正する。同じ間違いを二度出さないために、台帳の側を直すのが重要。
